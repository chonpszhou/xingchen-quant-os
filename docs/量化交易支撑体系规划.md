# 量化交易支撑体系规划（软性 + 硬性）

> 版本：v1.0 · 整理时间：2026-08-11  
> 适用定位：个人 / 小团队 · 多市场（A股 / 港股 / 美股 / 虚拟货币 / 期权）· 研究驱动型量化  
> 配套资产：星辰投研团（数据源检查 / 自选股 / 自动化任务）+ paddy-quant-workbench（行情接入 / 信号 / 回测 / 研报 / GEX）

---

## 0. 规划目标

把「学习 + 手工研究」升级为「可持续、可回测、可复盘、可灰度上实盘」的量化支撑体系。

判断标准：

- 任何策略想法都能在 1 天内跑出一版可复现回测（数据 + 回测口径固定）
- 任何实盘操作都有最小风控兜底（仓位 / 止损 / 频率 / 断线）
- 每周有固定复盘，每月有绩效归因，能说清盈亏来自 alpha 还是运气

## 1. 硬性支撑（硬实力）

### 1.1 数据基础设施

| 数据域 | 需要什么 | 现状 | 缺口 / 建议 |
|--------|---------|------|------------|
| 行情 | 实时 + 历史 + 前复权；A股/港股/美股/加密 | ✅ akshare / yfinance / ccxt / 东财直连，连接检查已验证 | 统一数据模型，收口成 DataHub；历史数据落库（见 1.1 存储） |
| 财务 | 三大报表、核心指标、业绩预告/财报日历 | ✅ akshare F10、东财美股财务 | 财报事件日历化，接入 tasks.yaml 财报监控 |
| 期权/衍生品 | 期权链、IV、Greeks、期限结构 | ✅ yfinance / akshare / Deribit 基础可用 | 补齐 IV rank / 期限结构计算（对标 gs-quant 口径） |
| 宏观/另类 | 利率、CPI、汇率、资金流、龙虎榜、舆情、链上 | ⚠️ 部分（东财资金流可用） | 舆情与链上数据按需引入，先不做重投入 |
| 数据工程 | 清洗、代码映射（A股6位/港股5位/美股ticker）、时区、复权、去重、缺失处理、增量更新、缓存 | ⚠️ 连接检查有格式校验 | 建立统一清洗层 + 增量更新 + 缓存（参考 pythonstock/stock 的按天缓存防封模式） |
| 存储 | 历史数据落库：SQLite / PostgreSQL + parquet；时序可选 QuestDB/InfluxDB | ❌ 目前无落库 | 先 SQLite + parquet（零运维），量大再上 Postgres/时序库 |

### 1.2 硬件与网络

| 项 | 建议 | 说明 |
|----|------|------|
| 本机 | macOS（现役） | 研究、回测、开发足够 |
| 云主机 | 1 台境外 VPS（低配即可） | 解决跨境数据抓取与 7x24 定时任务；避开本地出口不稳定问题（本次已实测 HTTPS 443 受限） |
| 网络 | 稳定出口 + 代理按需 | 境外接口（Yahoo/交易所）需稳定代理；加密交易所按地区轮询（Binance 451 → OKX/Gate/Deribit） |
| 存储备份 | SSD + Time Machine/云备份 | 代码、笔记、回测结果、密钥备份；本地+云端双份 |
| 高频 | 个人阶段不需要 co-location | 若做加密高频/做市，再考虑机房或交易所就近 VPS |

### 1.3 软件与技术栈

- **语言**：Python 为主，SQL 必备，Rust/C++ 可选（性能敏感处）
- **数据**：pandas / polars；缓存 parquet；ORM 或 SQLAlchemy
- **回测**：研究用 vectorbt / backtesting.py；A股规则模拟用 rqalpha；ML 因子用 qlib
- **机器学习**：sklearn / lightgbm / pytorch；实验管理 MLflow（或轻量版：每次实验存配置+结果+seed）
- **工程**：git + CI（现成 GitHub Actions）、YAML 配置（已用）、cron/APScheduler 调度（已设计）、日志与健康检查
- **监控告警**：日志落盘 + 推送通道（IM/邮件已配占位）；关键任务失败要能告警

### 1.4 交易执行

| 层 | 内容 | 现状 | 建议 |
|----|------|------|------|
| 账户/API | 券商接口（easytrader/miniqmt）、加密交易所（ccxt）、美股（Alpaca/IBKR） | ❌ 未接入 | 先接模拟盘，再小资金灰度 |
| 模拟盘 | dry-run / paper trading | ⚠️ freqtrade/Backtrader 自带 dry-run 可用 | 与实盘共用同一套策略代码 |
| 风控系统 | 下单前校验（价格偏离%、单笔/总仓位上限、频率限制）、熔断、断线重连、订单状态机 | ❌ | 上实盘前的硬门槛，最小集见第 5 节 |
| 交易日历 | 多市场时区/节假日/冬夏令时 | ⚠️ 未处理 | 任务调度必须挂交易日历（A股 T+1、美股夏令时、加密 7x24） |

### 1.5 安全与合规

- **密钥管理**：环境变量 → 1Password/Keychain；禁止入库（.gitignore 已加 .env）；API 密钥定期轮换
- **最小权限**：交易所/券商 API 只开交易所需权限，提现密钥与交易密钥分离
- **审计**：所有实盘操作留日志（时间、标的、价格、数量、理由）
- **合规**：不同市场规则差异（A股 T+1 涨跌停、加密资金费率、美股盘前盘后）；税务与报备按当地法规；注意平台条款（如 Binance 地区限制）

## 2. 软性支撑（软实力）

### 2.1 知识体系

| 领域 | 关键内容 | 优先级 |
|------|---------|--------|
| 金融市场 | 资产类别、订单簿、市场微观结构、流动性、做市 | 高 |
| 统计/计量 | 收益率分布、平稳性/协整、因子模型、风险模型（VaR/波动率）、回归陷阱 | 高 |
| 金融数学 | 期权定价、Greeks、IV 曲面、随机过程 | 中（期权线高） |
| 编程工程 | Python、SQL、git、调试、性能（向量化） | 高 |
| 机器学习 | 特征工程、过拟合控制、交叉验证、walk-forward、模型评估 | 高 |
| 市场规则 | A股 T+1/涨跌停/停牌、港股、美股财报季、加密 7x24/资金费率/清算 | 高 |

### 2.2 方法论与思维

- **科学方法**：假设 → 数据验证 → 样本外回测 → 模拟 → 实盘 → 复盘；每一步可复现
- **反过拟合**：警惕数据窥探、多重检验（试 100 个参数必有过拟合）、幸存者偏差、未来函数；用 walk-forward 和参数稳健性检验
- **风险管理思维**：仓位管理（凯利公式的保守版本）、单笔止损、回撤预算（如 20% 熔断）、尾部风险（黑天鹅 / 流动性枯竭）
- **批判性思维**：区分 alpha 与 beta/运气；做业绩归因（哪个市场/哪个因子/哪个时段贡献）；怀疑一切惊艳回测
- **心理与纪律**：执行纪律（信号出现就执行，不临时改）、止损纪律、情绪管理（连续亏损后强制降仓）、决策日志（写理由，复盘时对照）

### 2.3 流程与制度

- **研究闭环**：想法 → 文献/GitHub 调研（已建 Top50 学习体系）→ 数据验证 → 回测 → 模拟 → 灰度实盘 → 复盘归档
- **日志体系**：交易日志（每笔决策理由+结果）、研究日志（每实验的假设与结论）、周报（已有 tasks.yaml 周报任务）
- **知识管理**：Obsidian 量化交易库（已建分类索引），策略/复盘/学习三线归档
- **信息源**：论文（SSRN/arXiv）、GitHub（awesome-quant 等）、社区（发明者/QuantConnect 论坛）、研报（东财/券商）

### 2.4 组织与协作（小团队可选）

- 角色：研究 / 开发 / 风控 / 运营 四职责可一人兼任，但**风控职责必须独立于策略开发**
- 协作：代码评审、策略评审（过拟合检查）、每周例会
- 资金：设定总资金、策略资金上限、风控止损线，决策权与执行权分离

## 4. 分阶段路线图

### 阶段一：研究地基（1-2 个月）

**目标**：数据可落库、回测可复现、知识有体系

- 硬性：历史数据落库（SQLite + parquet）；统一 DataHub 收口 akshare/yfinance/ccxt；回测绩效口径固定（收益/回撤/夏普/胜率/盈亏比）
- 软性：过掉 GitHub Top50 学习路线的「数据关 + 回测关」；建立 Obsidian 研究日志模板
- 里程碑：任一策略想法 1 天内出可复现回测；连接检查全绿（含推送凭证）

### 阶段二：策略验证（2-4 个月）

**目标**：策略库成型，进入模拟盘

- 硬性：策略库版本化（git 标签 + 每策略配置文件）；引入 qlib 因子管线；接入交易日历
- 软性：完成「策略/因子关 + 衍生品关」；每策略过 walk-forward + 参数稳健性；建立策略评审清单（反过拟合检查）
- 里程碑：3-5 个通过评审的策略进入 paper trading；周报自动生成（tasks.yaml 落地）

### 阶段三：小资金实盘（4-6 个月）

**目标**：最小风控 + 灰度上实盘

- 硬性：风控最小集（见第 5 节）；easytrader/ccxt 实盘接口接入；订单日志与审计；断线重连
- 软性：交易日志制度强制执行；连续亏损降仓规则；决策与执行分离
- 里程碑：单一策略、最小仓位（如总资金 5-10%）连续运行 1-2 个月，无重大风控事故

### 阶段四：迭代优化（长期）

**目标**：组合管理 + 持续改进

- 硬性：组合层优化（多策略资金分配、相关性控制）；实验管理（MLflow 或轻量方案）；可选云主机 7x24 任务
- 软性：月度绩效归因；淘汰策略机制（连续 N 月不达标即下线）；持续学习（论文/社区/GitHub）
- 里程碑：月度报告自动生成；组合夏普与回撤达到预设目标

## 5. 优先级建议：先做这三件事

1. **数据落库 + 统一访问层**：把 akshare/yfinance/ccxt 收口为 DataHub，历史数据落 SQLite + parquet，增量更新 + 缓存。没有它，回测和策略开发全是重复劳动。
2. **回测与实验标准化**：固定绩效口径（收益/最大回撤/夏普/胜率/盈亏比 + walk-forward），每策略一个配置文件进 git。杜绝“回测惊艳、实盘翻车”。
3. **风控最小集**（上实盘前必须）：单笔仓位上限（如总资金 2%）、单策略总仓位上限（如 30%）、单笔止损（如 -3% 或 ATR 止损）、单日最大亏损熔断（如 -5% 暂停当日交易）、断线不追单。风控代码与策略代码分开评审。

> 先软件性、再硬性：方法论（反过拟合、风险管理）没立起来之前，投入再多的服务器和 API 也只是把错误放大得更快。
