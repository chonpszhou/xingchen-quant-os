# 星辰投研团 · 平台架构设计（v4.0，对标成熟开源量化平台）

> 依据：GitHub 开源平台架构研究（vnpy / qlib / freqtrade / QUANTAXIS / jesse）
> 结论先行：本系统此前是“脚本集合 + 看板”，缺少专业平台的事件驱动核心与统一抽象。
> 本文给出差距分析、目标架构、以及已实现的核心引擎（engine/）。

---

## 一、成熟平台架构范式（GitHub 实证）

| 范式 | vnpy | freqtrade | qlib | 本系统(v3) |
|------|------|-----------|------|------------|
| 事件驱动核心 | EventEngine（事件总线） | 主循环+事件 | 工作流引擎 | ❌ 脚本顺序执行 |
| 网关/交易所抽象 | Gateway（统一行情+交易回调） | exchange（ccxt 封装） | 数据Provider | ⚠️ datahub 函数集合，无统一接口 |
| 策略基类+动态加载 | Template + 模块注册 | Strategy + resolvers | Strategy 层 | ❌ 三个脚本各自为政 |
| 数据对象统一 | object.py（Bar/Tick/Order/Trade） | 数据类 | 统一数据结构 | ❌ 各脚本自造 DataFrame |
| 回测=实盘同一套代码 | BacktestingEngine 复现实盘接口 | dry-run 同接口 | 回测隔离无未来函数 | ❌ 回测/纸面两套代码 |
| 配置驱动 | 全局 setting | configuration schema | 配置+表达式 | ⚠️ 部分配置（tasks.yaml） |
| 内嵌风控 | 风控模块 | 交易前检查 | - | ⚠️ 事后监控，未入交易循环 |
| RPC 控制面 | UI/GUI | REST API/Telegram/WebUI | - | ⚠️ 看板只读（后加操作台） |
| 持久化 | database.py | persistence（sqlite） | 点对时数据库 | ⚠️ parquet+json，无交易流水 |

## 二、目标架构（v4.0）

```
┌─────────────────────────────────────────────────┐
│  控制面：看板(操作台) / CLI / 推送 / 定时调度      │
└───────────────┬─────────────────────────────────┘
                │ 命令/配置
┌───────────────▼─────────────────────────────────┐
│  MainEngine（总引擎）                            │
│   · 组件注册（data/strategy/executor/risk）      │
│   · 事件总线（行情→策略→风控→执行→回报）          │
└──┬──────────┬──────────┬──────────┬────────────┘
   │          │          │          │
┌──▼───┐  ┌───▼────┐  ┌──▼─────┐  ┌─▼─────────┐
│Data  │  │Strategy│  │Risk    │  │Executor   │
│Service│ │ 基类+注册│ │Engine  │  │Paper/实盘 │
│(行情/ │  │on_bar/ │  │(交易前/│  │(统一接口)  │
│财务/  │  │on_tick │  │ 后检查)│  │           │
│期权)  │  │        │  │        │  │           │
└──┬───┘  └───┬────┘  └──┬─────┘  └─┬─────────┘
   └──────────┴──────────┴──────────┘
        BacktestEngine（回测=实盘同一套代码）
```

设计原则（对标 vnpy/freqtrade）：
1. **策略只写逻辑，不碰数据源/执行/风控**（接口隔离）
2. **回测与纸面/实盘跑同一份策略代码**（杜绝“回测一套、实盘一套”）
3. **事件驱动**：Bar 到达 → 策略信号 → 风控检查 → 执行 → 回报写回（可扩展实时行情）
4. **配置驱动策略注册**：新增策略 = 写一个类 + 注册，不改主流程

## 三、已实现（engine/ 核心，v4.0 第一层）

| 模块 | 对标 | 状态 |
|------|------|------|
| `engine/events.py` | vnpy EventEngine | ✅ 事件对象+总线 |
| `engine/object.py` | vnpy object.py | ✅ BarData/OrderData/TradeData |
| `engine/data_service.py` | vnpy DataFeed / freqtrade data | ✅ 统一行情接口（封装 datahub） |
| `engine/strategy.py` | vnpy Template / freqtrade Strategy | ✅ 策略基类+注册表 |
| `engine/executor.py` | freqtrade exchange | ✅ 执行接口 + PaperExecutor |
| `engine/risk.py` | 内嵌风控 | ✅ 交易前检查（回撤/持仓上限） |
| `engine/main_engine.py` | vnpy MainEngine | ✅ 总引擎+组件注册 |
| `engine/backtest.py` | vnpy BacktestingEngine | ✅ 同一 Strategy 接口回测 |

## 四、迁移路径（渐进，不破坏现有系统）

1. 核心引擎（本次）→ 2. 三策略迁移到 Strategy 接口（双动量先行示范）
   → 3. 回测/纸面统一走 BacktestEngine → 4. 实盘 Executor 即插即用
   → 5. 持久化交易流水 → 6. 实时行情事件接入

> 现有 datahub/factors/scripts 作为“研究/批处理层”继续可用；engine/ 作为
> “平台运行层”在其上，两者通过 DataService 衔接。
